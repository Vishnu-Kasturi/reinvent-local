# On-the-Fly Gnina Docking as REINVENT4 Reward

This guide explains how to use **Gnina** molecular docking as a live reward signal
during RL or Mol2Mol runs. Every batch of generated molecules gets docked against
your receptor, and the binding affinity feeds into the geometric-mean reward.

## Architecture

```
REINVENT generates SMILES batch (e.g. 16 molecules)
        │
        ▼
GninaDock scoring component
  ├── RDKit: SMILES → 3D conformer (SDF)
  ├── Gnina: dock each ligand vs receptor.pdbqt (parallel workers)
  └── Return affinity (kcal/mol) → reverse_sigmoid transform → reward
        │
        ▼
Combined with QSAR (pIC50, solubility), QED, SA score, etc.
```

## Prerequisites

### 1. Install Gnina

```bash
# Option A: conda (recommended on DGX/Linux)
conda install -c conda-forge gnina

# Option B: build from source
git clone https://github.com/gnina/gnina.git && cd gnina && mkdir build && cd build
cmake .. && make -j$(nproc) && sudo make install

# Verify
gnina --version
```

### 2. Install receptor prep tools

```bash
conda install -c conda-forge openbabel   # obabel for PDB → PDBQT
# OR
pip install meeko                         # mk_prepare_receptor.py
```

### 3. Prepare your receptor

Place your files in `docking/`:

```
docking/
├── receptor.pdb          # your input
├── receptor.pdbqt        # generated by prep script
├── ref_ligand.sdf        # co-crystallized ligand (for autobox)
└── grid.json             # auto-computed grid parameters
```

```bash
python Preprocess/scripts/prepare_receptor_for_gnina.py \
    --input docking/receptor.pdb \
    --output docking/receptor.pdbqt \
    --ref_ligand docking/ref_ligand.sdf \
    --write_grid docking/grid.json
```

## Usage

### RL with docking reward (JAK2 example)

```bash
# Edit REINVENT4/configs/jak2_rl_gnina.toml:
#   - Set params.center_x/y/z from docking/grid.json
#   - Or use params.autobox_ligand

./pipeline.sh --target jak2 --step 4   # if TL checkpoint already exists

# Or run directly:
cd REINVENT4
reinvent -l ../logs/jak2_rl_gnina.log configs/jak2_rl_gnina.toml
```

### Mol2Mol with docking reward (PD1-PDL1 example)

```bash
./run_mol2mol_pipeline.sh --target pd1_pdl1 \
    --config pd1_pdl1_mol2mol_gnina.toml
```

### Standalone batch test (before running full RL)

```bash
echo -e "CCO\nc1ccccc1O" | python Preprocess/scripts/gnina_dock.py \
    --receptor docking/receptor.pdbqt \
    --autobox_ligand docking/ref_ligand.sdf \
    --autobox_add 4 \
    --exhaustiveness 4 \
    --n_workers 2
```

## TOML scoring component reference

```toml
[[stage.scoring.component]]
[stage.scoring.component.GninaDock]
[[stage.scoring.component.GninaDock.endpoint]]
name                    = "GninaAffinity"
weight                  = 3.0
transform.type          = "reverse_sigmoid"
transform.high          = -6.0    # weak binding → low reward
transform.low           = -12.0   # strong binding → high reward
transform.k             = 0.3
params.receptor_path    = ["../docking/receptor.pdbqt"]
params.gnina_executable = ["gnina"]
params.autobox_ligand   = ["../docking/ref_ligand.sdf"]
params.autobox_add      = ["4.0"]
params.exhaustiveness   = ["4"]
params.num_modes        = ["1"]
params.cnn_scoring      = ["rescore"]
params.docking_mode     = ["full"]
params.n_workers        = ["4"]
params.use_gpu          = ["true"]
params.cache_dir        = ["../docking/gnina_cache"]
```

### Grid box options

| Method | TOML params | When to use |
|--------|-------------|-------------|
| **Autobox** | `autobox_ligand` + `autobox_add` | You have a co-crystallized ligand |
| **Explicit** | `center_x/y/z` + `size_x/y/z` | You know the binding site coordinates |

### Docking modes

| Mode | `docking_mode` | Speed | Use case |
|------|----------------|-------|----------|
| Full search | `full` | Slowest | Best accuracy, default |
| Local minimize | `minimize` | Fast | Ligand already near binding site |
| Score only | `score_only` | Fastest | Pre-positioned 3D conformers |

## Performance tips

Docking is the bottleneck. For on-the-fly RL:

1. **Reduce `batch_size`** to 8–16 (default RL uses 64)
2. **Use GPU**: set `device = "cuda"` and `params.use_gpu = ["true"]`
3. **Low exhaustiveness**: `exhaustiveness = 4`, `num_modes = 1`
4. **Enable caching**: `params.cache_dir` avoids re-docking repeated SMILES
5. **Parallel workers**: `n_workers = 4` (match your CPU cores)
6. **Two-stage strategy**: Stage 1 with QSAR only, Stage 2 add GninaDock
7. **CNN fast mode**: `params.cnn_scoring = ["rescore"]` (not `"all"`)

Typical timing on DGX A6000: ~2–5 sec/molecule with GPU, ~10–30 sec/molecule CPU-only.

## Combining with existing scorers

The geometric mean combines all weighted components. A typical multi-objective setup:

| Component | Weight | Speed | Role |
|-----------|--------|-------|------|
| JAK2pIC50 / PD1PDL1pIC50 | 2–3 | Fast (XGBoost) | Bioactivity proxy |
| GninaAffinity | 3–5 | Slow (docking) | Structure-based validation |
| QED / SAScore | 1 | Fast | Drug-likeness filter |
